# 02 · 信息流与闭环

## 总流向

```
① 进来               ② 看与理解                 ③ 去处（可多个并存）            ④ 回看
随手记 C08 ──┐
信息收集 C13 ─┤      收件流（全部来源）          推送 → 今日「待采纳」→ 采纳 = 行动      复盘（日/周/月）
QQ 群 C15 ───┼──▶  材料详情：原文、媒体、  ──▶  直接转行动 / 挂到已有行动              项目页「关联」
日记 C11 ────┤      上下文、AI 结果、           入库 → 知识库 → 知识节点               材料历史
剪藏 V11 ────┘      我的理解、已读、已消化       关联项目（参考 / 已确认需求）           写入回执
                                              稍后 / 归档（只标记，不删）
项目交接 / 工程 C02/C04 ─────────────────────▶ 待我决策（请求）→ 我回应 → 写回请求，项目侧可见
```

## 每一步用户能做什么、结果在哪

| 步骤 | 用户动作 | 结果显示在 | 对应需求 |
| --- | --- | --- | --- |
| 记一条 | `Ctrl J` 或随手记卡；选类型（想法 / 问题 / 待办线索 / 摘录 / 原话） | 收件流顶部；回执带 `系统/随手记/随手记收件箱.md` | R19、S01 |
| 采集 | 信息收集页选平台 + 方式（浏览器采集 / 导入文件 / 刷新存档） | 本次运行：成功 / 重复 / 失败 / 缺媒体分开计数；刷新存档不算新采集 | R20、S03 |
| QQ | 勾选白名单群 →「开始收集」或「读取存档」 | 每个群单独结果；失败群写原因；成功群的消息带上下文 | R21、S04 |
| 读 | 打开材料；**明确**点「标记已读」（打开不算已读） | 材料事实「已读 时间」 | R03 |
| 理解 | 写「我的理解」；确认「已消化」 | 待消化卡减少；可撤回 | R03 |
| AI 批次 | 在收件里多选 →「新建处理批次」→ 确认发送 | 批次页：每条 AI 结果 / 失败 / 未知；未知可「重新读取」，失败可单条重试；**不自动重发** | R22、S05 |
| 推送 | 材料「推送到待采纳」 | 今日待采纳；已在待采纳时不重复推送 | R04、S06 |
| 采纳 | 待采纳行「采纳」/「不采纳（可写原因）」/「稍后」/「撤回」 | 采纳 → 行动（去重，撤回再采纳不会多建）；不采纳保留原文与原因 | S06、S26 |
| 多出口 | 同一材料：入库 + 关联项目 + 转行动 | 材料「去处」三项并列；补笔记不抹关系 | R02、S07 |
| 多来源一个行动 | 第二条材料「挂到已有行动」 | 行动「来源」列出两条材料 | S08 |
| 回应请求 | 待我决策详情：按类型给出 通过 / 需修改 / 选方案 / 已操作 / 补充 / 稍后 / 不适用；「需修改」「补充」「不适用」必须写文字 | 写回请求文件；请求转「已回应 · 等谁推进」；刷新仍在 | R10、R11、S10、S11 |
| 验收 | 验收类请求可「安排一条验收行动」 | 行动勾掉 ≠ 验收通过；结论要回到请求里给 | S13 |
| 复盘 | 看某天完成数 → 点柱子 → 当天行动 | 直接打开原行动（不是副本）；未知天单独标出 | R26、S16 |

## 今日「待采纳」与「待我决策」怎么并存

| | 待采纳（Approval） | 待我决策（Decision） |
| --- | --- | --- |
| 本质 | 别人建议的**事情**，等我承诺 | 卡住的**问题**，等我回答 |
| 来自 | 材料推送、AI 批次建议、项目提出 | 项目当前交接里「需要用户」的事项、工程验收点 |
| 我的动作 | 采纳 / 不采纳 / 稍后 | 通过 / 需修改 / 选方案 / 已操作 / 补充 / 稍后 / 不适用 |
| 结果 | 采纳 = 建一条行动（去重） | 回应写回请求；项目侧看到「已回应」 |
| 两者关联 | 某条待采纳可以指向请求（如「安排 10 分钟重载扩展」对应请求 d03） | 请求可以生成验收行动 |

今日页把两者放在不同标签里，画板上是两张不同的卡，不会互相冒充。

## 不会自动发生的事

- 随手记**不会**自动变成任务；推送**不会**自动建行动；采纳**不会**自动排日期以外的东西。
- AI 结果**不会**自动标「已消化」；AI 建议的理解程度要我点「接受」才生效。
- 勾掉验收行动**不会**让请求通过；记录验收**不会**宣布项目完成。
- 失败或「不确定」的写入**不会**自动重发。
