# 01 · 对象模型：先分清八类东西

仪表盘里所有界面都是这八类对象的**不同视图**。同一个对象出现在多个地方（画板卡片、完整页、项目页、复盘），它的身份和处理结果都是同一份——在一处勾掉，其他地方同时变化（S23）。

| 对象 | 回答什么 | 界面在哪 | 不能混为一谈 |
| --- | --- | --- | --- |
| **输入源**（Source） | 数据从哪个渠道来、现在能读到什么、健康吗 | 接入源页 `/c/sources`、卡片「属性」面 | 源在线 ≠ 内容完整；平台名 ≠ 某条内容的精确出处 |
| **原始材料**（Material） | 当时到底收到 / 写下了什么（原文全文） | 收件 `/c/inbox`、材料详情 `/c/inbox/m/:id` | 摘要 ≠ 原文；标题 ≠ 全部内容 |
| **处理记录**（材料上的事实） | 读过没、AI 结果、我的理解、已消化、推送、稍后、归档、关联 | 材料详情右侧「事实」与历史 | 读过 ≠ 理解；刷新 ≠ 处理；**多项事实同时成立**，主状态只是扫读用 |
| **待采纳**（Approval） | 有人（AI / 项目 / 我）建议做的事，我还没承诺 | 今日页「待采纳」、待采纳卡 | 推送 ≠ 已经建了行动；采纳才建行动（去重） |
| **请求 / 决策**（Decision） | 现在卡在哪个**必须由我回答**的问题上 | 待我决策 `/c/decisions` | 普通下一步、待读资料、知识问题**不进**这里 |
| **行动**（Action） | 我明确承诺要做的一件事 | 今日 `/c/today`、行动详情 `/c/today/a/:id` | 完成「阅读样例」≠ 验收通过；完成行动 ≠ 项目完成 |
| **项目与工作项**（Project / WorkItem） | 长期目标，以及这一轮具体改什么 | 项目 `/c/projects/:id` | 一张卡不必是一个项目；一个 Commit ≠ 一个阶段完成 |
| **知识与认知**（KNode / LibraryDoc / Question） | 保存了什么可信资料，我理解到哪 | 知识 `/c/knowledge` | 入库 ≠ 掌握；AI 觉得重要 ≠ 我确认 |

## 关系（简图）

```
输入源 ──产生──▶ 原始材料 ──处理事实（多项并存）──┬─▶ 推送 ─▶ 待采纳 ─采纳─▶ 行动
                                                ├─▶ 直接转行动 / 挂到已有行动（多材料 → 一个行动）
                                                ├─▶ 入库 ─▶ 知识库文档 ─▶ 知识节点（我标理解程度）
                                                └─▶ 关联项目（参考 / 已确认需求）
项目交接 / 工程 ──投影──▶ 请求（待我决策）──我回应──▶ 写回请求 + 项目侧可见
                                         └─ 验收类：可安排「验收行动」（做完 ≠ 通过）
行动 + 日记 ──汇总──▶ 复盘（衍生视图，不产生新数据）
```

## 每个对象都带的三样东西

- **精确来源 Ref**：`source`（接入源编号）+ `label` + `path` / `url` / `anchor` + 时间。界面上只展示示例路径，未连接文件系统。
- **历史 Hist[]**：谁（我 / AI / 系统 / 工程 / 项目 / 外部）在什么时候做了什么。
- **写入回执 Receipt**：每次写入都有结果：成功（含落到哪个文件）、失败、不确定、冲突。设置页「写入回执」可以查全部。

字段细节见 [架构/02-数据契约](../架构/02-数据契约.md)。
