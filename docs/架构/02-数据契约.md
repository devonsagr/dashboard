# 架构 02 · 数据契约

> 对应 `src/data/types.ts`。这是前后端的**唯一约定**：后端返回这些形状，前端只按这些字段显示。字段名可以由 Codex 调整，但请同时改 `types.ts` 并让 `npm run build` 通过。
> 约定：`ISO` = 带时区时间（`2026-10-17T09:30:00+08:00`）；`Day` = `YYYY-MM-DD`（Asia/Hong_Kong）。**可选字段缺失 = 不知道**，界面显示“未知 / 未提供”，不当作 0。

## 两种数据

| | 共享对象 | 卡片私有数据 |
| --- | --- | --- |
| 放哪 | `src/data/types.ts` + `store.ts` | `src/cards/<id>/model.ts`（或 store.ts 里）+ `store.ts`（`cardStore`） |
| 什么时候用 | 多张卡要读写，或要互相引用（材料、行动、待采纳、请求、项目、知识、日记、接入源、回执） | 只有这张卡关心（QQ 群勾选、节点采样、收藏的批注与任务、便签文字） |
| 改字段 | 影响所有用到的卡，要同时改 `types.ts` 并让构建通过 | 只影响这张卡 |
| 本页 | 下面各节 | 只列收藏（最复杂的一张），见文末 |

## 公共

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `Ref` | `source` `label` `path?` `url?` `anchor?` `at?` | 精确来源（R01）。`source` 是接入源编号；`path` 是 Vault 相对路径；`anchor` 是块 ID / 标题；`at` 是资料时间。界面用 `RefLine` 显示，`path` 仅展示为文本，不打开文件 |
| `Hist` | `at` `by` `text` | 对象历史一条。`by` ∈ 我 / AI / 系统 / 工程 / 项目 / 外部 |
| `Receipt` | `id` `op` `label` `at` `status` `path?` `targetId?` `detail?` `error?` | 写入回执。见 [03-写入语义与回执](03-写入语义与回执.md) |

## 接入源与诊断

| 类型 | 关键字段 | 说明 |
| --- | --- | --- |
| `Source` | `id` `name` `group` `mode` `health` `provides` `via` `location?` `count?` `lastReadAt?` `asOf?` `limits?` `feedsFlow` | `health` ∈ ok 正常 / stale 陈旧 / offline 离线 / partial 部分 / missing 缺文件 / unverified 未核验 / planned 计划 / unconfigured 未配置。`lastReadAt`（我们最后读它）与 `asOf`（数据本身截至）分开 |
| `Diagnostic` | `level` `area` `text` `at` `path?` `object?` `affects` `resolved?` | 解析 / 写入实际出的错，与源健康分开（R27）。`affects` 写“影响了什么” |

## 材料（收件）`Material`

| 字段 | 说明 |
| --- | --- |
| `kind` | capture 随手记 / collect 收藏 / qq / diary / clip / project / health / handwrite |
| `sourceId` `channel` `platform?` `group?` | 来自哪个源、哪个渠道、平台或群 |
| `title` `text` | **`text` = 原文全文，只读，不裁剪不改写** |
| `contentAt?` / `receivedAt` | 内容本身时间 vs 进入系统时间，分开显示 |
| `ref` | 原处定位 |
| `read?` | 用户**明确**标记已读的时间（打开不算） |
| `ai` | `state` none / sent / result / failed / unknown；`summary` `suggestion` `confidence` `error` `batchId` |
| `digested?` | 只有用户点“确认已消化”才有（`note` 必填一句理解） |
| `note?` | 我的理解 / 批注 |
| `later?` `archived?` | 稍后、归档 |
| `outputs[]` | 去向：approval / action / knowledge / project，带 id 与路径 |
| `projectLinks[]` | 关联项目，`as` = 参考 / 已确认需求 |
| `media?[]` `gaps?[]` | 媒体是否可用（不可用要写 `reason`）、信息缺口 |
| `context?[]` | QQ 上下文，`self` 标出本条 |
| `batchIds[]` `dupOf?` | 所在处理批次、重复于 |

派生主状态 `MaterialMain`（`store.mainState`）：已归档 > 稍后 > 已落地（有 action/knowledge 去向）> 已推送（有 approval）> 已消化 > AI 有结果 > AI 处理中 > 已读 > 新收到。**后端不用存主状态**，存事实即可。

## 待采纳 `Approval`

`title` `body?` `group` `sourceId` `by`（AI / 我 / 工程）`createdAt` `refs[]` `materialIds[]` `state`（pending / adopted / rejected / later）`decidedAt?` `reason?` `actionId?` `projectId?` `decisionId?` `suggestDate?`。
采纳 = 生成**一条**行动（`actionId` 回填）；撤回到待采纳后再次采纳：复用原来那条行动（若已被删除则恢复），不重复生成。

## 行动 `Action`

`title` `body?` `date?` `time?` `priority`（高 / 中 / 低）`order` `createdAt` `path` `done?` `archived?` `deleted?` `projectId?` `workItemId?` `decisionId?` `approvalId?` `kind?`（验收行动）`refs[]` `materialIds[]` `history[]`。
分区 `ActionSection`（`store.sectionOf`）：deleted > archived > done > overdue（date < 今天）> today > later（date > 今天）> undated。

## 待我决策 `Decision`

| 字段 | 说明 |
| --- | --- |
| `kind` | 验收 / 选择 / 操作 / 补充 / 个人 |
| `raisedBy` `path` `asOf` | 谁提的、请求文件、资料截至 |
| `whyNow` `blocks` `done[]` `uncertain[]` | 为什么现在要我、不决定会卡住什么、已完成、仍不确定 |
| `entry?` `criteria[]` | 验收入口（链接 / 文件）与标准 |
| `options?[]` `recommend?` | 选项与推荐（`by` AI / 项目），推荐只是建议 |
| `status` | open / later / resolved / dismissed |
| `freshness` | current / stale / superseded（`supersededBy`）/ revoked；`freshNote` |
| `response?` `responses[]` | 当前回应与历次回应。`ResponseKind` 通过 / 需修改 / 选方案 / 已操作 / 补充 / 稍后 / 不适用；`需修改` 必须有 `text`；`已操作` 带 `verify` 待核实 |
| `after?` | 回应后在等谁（AI / 我 / 外部 / 项目） |
| `actionIds[]` `refs[]` `history[]` | 由它生成的验收行动等 |

## 项目 `Project` / `WorkItem`

- `Project`：`ownership`（产品项目 / 卡片模块 / 独立工具）`parentId?` `status`（9 种，含 等待用户 / 等待外部 / 部分完成 / 受阻）`stage` `purpose` `scenario` `scope{in,out}` `doneDef[]` `requirements[]`（有效 / 已替代 / 待确认 + ref）`modules[]` `docs[]`（`role` 权威 / 镜像 / 历史）`follow{current,next,owner,blocker,asOf}` `eng{registered,reachable,repo,branch,worktree,head,dirty,commits,asOf,note}` `handoff{lastReliable,unfinished,failed,resumeWith}` `workItems[]` `refreshes[]`（普通读取 / AI 语义刷新 / 投递，各自状态）`path` `asOf`。
- `WorkItem`：`trigger{text,ref}` `change` `criteria[]` `version?` `checks[]`（`CheckKind` 本地检查 / 浏览器效果 / 真实设备 / 用户认可，`state` 通过 / 未通过 / 未做 / 等待）`gaps[]` `nextOwner` `decisionIds[]` `actionIds[]`。**“本地检查通过” ≠ “用户认可”**，界面分开显示。

## 收集 / QQ / 批次

> 旧「信息收集」的 `Platform` / `CollectRun` 仍在共享层（收件和接入源还在引用），新的收藏流程用收藏卡自己的模型（文末）。

- `Platform`：`id`（x / bili / xhh / yt / reddit）`scope` `limits` `modes[]`（浏览器采集 / 导入文件 / 刷新存档）`rawPath` `matPath`。
- `CollectRun`：`status` running / ok / partial / failed；`counts{new,dup,failed,missingMedia}`；`path`；`error?`。
- `QQGroup`：`whitelisted` `lastCollected?` `coverage` `members?`；`QQRun.groups[]` 逐群状态（一个群失败不影响其他群）。
- `ProcBatch`：`source` `materialIds[]` `status` draft / confirmed / partial / done；`approvalIds[]` `path`。单条可重试（`retryItem`）、可重新读取 AI 状态（`recheckItem`）。

## 日记 `DiaryDay` / `DiaryFile`

一天三个文件：`用户原文` / `生活日记整理版` / `AI项目日志`。`state` ∈ exists / missing / empty / failed（`error`）。`mtime` 是文件修改时间。缺文件不自动创建，用户点“新建”才写。

## 知识

- `KNode`：`title` `parent?` `body` `known?`（懂 / 半懂 / 不懂 / 想拓展，**只由用户设定**）`knownAt?` `aiSuggest?`（AI 建议 + 理由，需用户接受）`notes[]` `relations[]`（依赖 / 相关 / 对比）`materialIds[]` `actionIds[]` `questionIds[]`。
- `LibraryDoc`：知识库里已确认的产物（`path` `source` `scope`）。
- `Question`：`text` `ref` `status` open / answered / dropped；`answer?`。

## 复盘

- `DayMeta`：`status` ok / unknown（`reason`）。没有记录的日子显示为“未知”，不是 0。
- `Reflection`：`key`（如 `day:2026-10-17`、`week:2026-W42`）`text` `at`。

## 本机运行时

## 健康 / 成本

- `HealthDay`：`steps?` `sleepMin?` `restingHr?` `spo2?`（缺 = 未同步，不是 0）`deviceAt?`（设备记录时间）`syncedAt?`（同步到我们的时间）`meals[]`（`estimate` 标出估算）`orders[]` `gaps[]`。
- `CostEntry`：`kind` 订阅 / 按量账单 / 估算；`amount?` 缺 = 未知；`currency` CNY / USD **不自动换算合计**；`period` `ref`。

## 材料的「主场」`Material.home`

`home?: { card, id }`：这条材料的完整内容在哪张卡里（目前只有 `favorites`）。收件里显示的是**投影**，材料页给「在收藏里打开 →」，不复制正文、图片、字幕。

## v5 新增字段

- `Material.topic?`：主题（用于落点规则）。
- `Material.ai`：增加 `intent`（按哪份备注做的）、`points`（要点）、`suggest`（'入库' | '自己处理'，只是建议）。
- `Material.route?`：`{ kind: '入库' | '自己处理', at, path, rule?, crossed?: number[], done? }`——③ 我选的结果。
- `Material.later`：以后读的放入时间（原「稍后」）。
- `MaterialMain`：新收到 / 已读 / 已写备注 / AI 处理中 / 待我选 / 自己处理中 / 已消化 / 已推送 / 已落地 / 以后读 / 已归档。
- `Project.lastReadAt?`：最后读取（与 `asOf` 资料截至分开）。
- 设置 `Settings`（`src/data/settings.ts`）：`cutoff`、`flow{pre,self,later,daily}`、`routes: RouteRule[]`、`subject: SubjectDoc[]`、`groups: Group[]`。
- 主体更新 `SubjectUpdate`（`src/data/subject.ts`）：`doc, tier('短期'|'候选'|'长期'), text, ref, by, at, state`。
