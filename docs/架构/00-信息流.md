# 00 · 信息流（v5 主线）

> 一句话：**来源 → 收到 → 我写备注 → AI 按备注初处理 → 我选去向 → 输出（日报 / 建议 / 推荐 / 主体上下文）**。
> 所有卡片都挂在这条线上；不在线上的卡（专注计时、电脑使用、B站倍速…）是工具，不参与流转。

## 1. 主线

```
来源（接入源 C01–C21 / P01–P06）
  │  内容时间 contentAt   ≠   取得时间 receivedAt
  ▼
收到（材料 Material，原文只读）
  │
  ▼  ① 备注：为什么收、想拿它做什么（人先写；AI 只按备注做，不猜）
  │        可选：只保存 / 以后读（悬置，随时拿出）
  ▼  ② AI 初处理：按备注出 摘要 + 要点 + 建议去向（只是建议）
  │        失败 / 不确定 → 明说，可重发；改了备注 → 提示结果按旧备注
  ▼  ③ 我选（两条互斥）
      A 直接入库 ── 按「落点规则」算路径 → 原文 + 备注 + 标签 + 来源 (+ AI 初处理) 写入
      B 我自己处理 ─ 读原文，划掉 AI 要点 → 「处理完了」= 已消化
  ▼
输出
  ├─ 日报（每天 04:00 起算；说明实际用了哪些来源、缺什么；可定稿）
  ├─ 建议 → 待采纳 → 今日行动（不自动执行）
  ├─ 新内容推荐（GitHub 热门 / 周报 / 关注作者；标内容本身的新旧）
  ├─ 决策 / 项目回流（我回应过的不会因项目没刷新而消失）
  └─ 主体上下文（AI 想写进 8 份文档的东西先进队列：短期生效可撤回 / 候选要接受 / 长期要确认）
```

AI 不替人做的事：不自动选 A/B、不宣布「已消化」、不把推测写进长期画像、不把旧内容说成今天新发布。

## 2. 在哪里操作

| 环节 | 入口 |
| --- | --- |
| 收到 / 备注 / 初处理 / 我选 | 收件卡 → 材料页「处理」三步（`src/ui/flow.tsx` FlowPanel）；收藏卡 → 条目右侧同样三步（`favorites/views/Annotate.tsx`） |
| 以后读 | 同上「以后读」按钮；收件筛选「以后读」、收藏「以后读」标签 |
| 落点规则 / 日切时刻 / 主体文档路径 / 群分组 | 设置页顶部四节（`src/ui/settings.tsx`，存 `pkd.v5.settings.v1`，不随样例重置） |
| 日报 | 日报卡（`src/cards/daily/`） |
| 主体上下文 | 主体上下文卡（`src/cards/context/`） |
| 群消息关注 / 钻研 | 群消息卡（`src/cards/qq/`） |

## 3. 落点规则（路由）

规则 = 平台 × 类型 × 主题 → 路径模板（`{平台}{类型}{主题}{日期}{标题}`）。`任意` 不加分，**越具体越优先**（命中的维度多者胜；同分取靠前的）。入库前预览会显示命中哪条规则，可单条改路径。改规则后，**还没入库的**材料预览立刻跟着变；已入库的保留当时写下的路径。实现：`src/data/settings.ts` `resolveRoute` / `matchRule`。

## 4. 一天从几点算

默认 **04:00**（设置可改）。`src/data/time.ts`：`dayKey(iso)` 把 00:00–03:59 归到前一天；`whyToday(contentAt, receivedAt)` 给出「昨天的内容 · 今天取得」这类理由。日报、群消息「今日关注」、收件都用它。

## 5. 状态（材料主状态）

新收到 → 已读 → 已写备注 → AI 处理中 → 待我选 → 自己处理中 / 已落地(入库) → 已消化；旁路：以后读、已推送、已归档。见 `src/data/store.ts` `mainState`。
