# 架构 01 · 层级与目录

> 一句话：用户看得见的只有三层——**画板 → 卡片 → 卡片完整页**。代码里一张卡 = 一个文件夹 = 一个独立模块；宿主只负责「把卡装上去」，不知道任何卡的内部。

## 为什么改（v3 → v4）

v3 里有一层用户看不见的「功能」（`features/<功能>/`），一个功能下挂好几种卡片 kind、几组路由；还有 `workbench/builtin`、`custom/` 两套平行目录。结果：

- 用户眼里的一张卡，在代码里要去三四个地方找；「月历」「日程」「待消化」看起来是卡，其实是别的功能的一个样子；
- 一个功能的代码出错，会连带它下面所有卡和完整页；
- 新加一张卡要先想「它属于哪个功能」，再改功能清单、注册表、路由。

v4 去掉了「功能」这一层：

| 用户看到的 | 代码里 |
| --- | --- |
| 画板（今日、项目、输入……） | `workbench/board/store.ts` 里的布局数据：哪些卡、放在哪、什么颜色、什么视图 |
| 卡片 | `src/cards/<id>/`：`manifest.ts` + `index.tsx` + 只属于它的文件 |
| 同一张卡的不同样子（列表 / 日程、收件流 / 待消化 / 流转） | 这张卡的**视图**：`manifest.views`，放到画板上时选，实例里存 `props.view` |
| 卡片完整页（放大 ⤢） | 这张卡 `index.tsx` 导出的 `Page`，挂在 `/c/<id>/*`，子页面它自己用相对路由分 |

## 目录

```
src/
├─ workbench/          宿主（不含任何卡片业务）
│  ├─ app/             外壳：顶栏、画板标签、面包屑、浮层、Ctrl K、Ctrl J 随手记、偏好、旧地址转发
│  ├─ board/           画板：规整栅格、拼贴、卡片外壳、属性面、颜色、布局存储
│  ├─ cards/           protocol.ts 协议 · registry.ts 登记表读取 · host.tsx 懒加载 + 出错隔离
│  └─ pages/           画板页、全部卡片（卡片库）、设置（含写入回执）
├─ cards/              卡片。一张卡一个文件夹
│  ├─ index.ts         登记处：一行一张卡（只 import manifest）
│  ├─ _template/       新卡模板
│  ├─ today/ approvals/ decisions/ diary/ review/ projects/ inbox/ quick-note/
│  ├─ favorites/       收藏（独立子项目，自带 README）
│  ├─ qq/ knowledge/ health/ ningshi/ node/ usage/ cost/ sources/ bili-speed/
│  └─ clock/ habits/ countdown/ sticky/ recent-docs/ quick-edit/ embed/ overdue/
├─ data/               共享对象（多张卡都要用的）
│  ├─ types.ts         对象契约 · store.ts 读写函数（= DataPort）· sample.ts 样例 · time.ts
│  └─ cardStore.ts     卡片私有数据的工具（每张卡自己的 store.ts 用它）
├─ ui/                 共享界面零件（无业务）：ui.tsx · objects.tsx · refs.tsx · write.tsx
└─ styles/             令牌与样式
```

## 一张卡的文件夹

| 文件 | 必须 | 内容 |
| --- | --- | --- |
| `manifest.ts` | 是 | `defineCard({...})`：id、名字、图标、类别、尺寸、视图、设置项、数据说明（来源 / 存储 / 刷新 / 写回）、`aliases`（旧 kind 迁移）、`carries`（承接旧卡）、`load: () => import('./index')`。**不 import 界面和数据** |
| `index.tsx` | 是 | `defineImpl({ Card, Page?, Meta?, Title?, Crumb?, Topbar?, LibraryExtra? })` |
| `store.ts` | 否 | 只属于这张卡的数据：`cardStore('<id>', init)` |
| 其他 | 否 | 页面、样例、样式、README |

## 隔离

| 规则 | 怎么保证 |
| --- | --- |
| 卡片之间不互相 import | 约定 + 评审；要跳到别的卡用链接 `/c/<id>/…` 或 `useOverlay().open` |
| 一张卡崩了只影响它自己 | `host.tsx` 给每张卡的正文、完整页、顶栏挂件各包一层 `CardBoundary`，显示「这张卡出错了 · 重试」 |
| 加载失败只影响它自己 | 每张卡的实现是单独代码块（`manifest.load` 懒加载），失败可重试 |
| 删掉一张卡不影响别的 | 删文件夹 + 删 `cards/index.ts` 一行；画板上已放的实例显示「未知卡片」，可移除 |
| 私有数据互不干扰 | 每张卡自己的 `localStorage['pkd.v5.card.<id>.v1']`（用户内容 `pkd.v5.content.<id>.v1`）；接后端时每张卡只换自己的 `store.ts` |

## 谁能 import 谁

| 位置 | 可以 | 不可以 |
| --- | --- | --- |
| `workbench/*` | `data`、`ui`、`cards/index.ts`（只拿 manifest） | 任何卡片的 `index.tsx` 或内部文件（只能经 `host.tsx` 懒加载） |
| `cards/<id>/*` | `workbench/cards/protocol`、`workbench/board/store` 的类型、`workbench/app/overlay`、`workbench/cards/registry`（只读：比如列出全部卡片）、`data`、`ui`、自己文件夹 | 别的卡片文件夹 |
| `ui/*` | `data` 的类型与时间工具 | `workbench`、`cards` |
| `data/*` | 无 | 任何界面代码 |

## 共享对象 vs 私有数据

- **共享对象**（`src/data`）：多张卡都要读写、或者要互相引用的东西——原始材料、行动、待采纳、请求、项目、知识节点、日记、接入源、写入回执。例：收藏卡把一条材料送去「待采纳」，今日行动卡才能看到。
- **私有数据**（`src/cards/<id>/store.ts`）：只有这张卡关心的——QQ 群勾选、节点采样、收藏的阅读批注与任务、便签文字。别的卡要用，就提升到共享对象，而不是去 import。

数据契约见 [02-数据契约](02-数据契约.md)；读写函数见 [04-接入层与DataPort](04-接入层与DataPort.md)。
